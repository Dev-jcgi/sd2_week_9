¿Cómo llegamos del Sprint 4 a la demo del 30 de noviembre?

Long image

A

Answer

Con una semana de integración y pruebas con alcance cerrado: se congela lo que entra, se prueba el recorrido completo entre los cinco módulos, se marca la versión v1.0.0 con un tag y se publica un release en GitLab; la demo muestra exactamente esa versión.

  1. El Sprint 4 cierra el 22 de noviembre; del 23 al 30 es integración, pruebas y demo.
  2. La fecha y los equipos ya no cambian: lo único que se ajusta es el alcance.
  3. Un tag de Git apunta a un commit exacto; el release le agrega notas y archivos.1

¿Qué pasa en la semana final?

Diagram structure
  • Cierre del Sprint 4 cierre
  • Integración de módulos integra
  • Congelar alcance congela
  • Tag v1.0.0-rc.1 rc
  • Ensayo de la demo ensayo
  • Release v1.0.0 release
  • cierre → integra
  • congela → rc
  • ensayo → release · solo correcciones
  • integra → congela
  • rc → ensayo
  1. Cerrar el Sprint 4 ↗

    Lo que no está fusionado en main con el pipeline en verde no cuenta como hecho.

  2. Integrar ↗

    Probar el recorrido completo: usuario, catálogo, pedido, pago y entrega juntos.

  3. Congelar ↗

    Desde aquí solo entran correcciones, no funciones nuevas.

  4. Candidato ↗

    Un tag v1.0.0-rc.1 marca la versión que se ensaya.

  5. Ensayar ↗

    Correr la demo dos veces con cronómetro, en la máquina de la demo.

  6. Publicar ↗

    Tag v1.0.0 y release en GitLab con sus notas.
