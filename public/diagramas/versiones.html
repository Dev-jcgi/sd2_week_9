¿Qué número de versión le toca a cada cambio del Delivery System?

Long image

A

Answer

Con versionado semántico (MAJOR.MINOR.PATCH): si rompes lo que otros módulos usan sube MAJOR, si agregas algo compatible sube MINOR y si solo corriges sube PATCH. Hoy todo está en 0.0.1-SNAPSHOT; la demo debería mostrar 1.0.0.

  1. La versión 1.0.0 define la API pública; en 0.y.z cualquier cosa puede cambiar.1
  2. En Maven, SNAPSHOT significa «en construcción»: la versión final no lo lleva.2
  3. Un CHANGELOG agrupa los cambios en Added, Changed, Fixed y Removed para cada versión.3

¿Cómo se publica una versión?

Diagram structure
  • Quitar -SNAPSHOT en los pom pom
  • MR aprobado y fusionado mr
  • Pipeline en verde en main ci
  • Tag anotado v1.0.0 tag
  • Release en GitLab con notas rel
  • ci → tag
  • mr → ci
  • pom → mr
  • tag → rel
  1. Cambiar la versión ↗

    ./mvnw versions:set -DnewVersion=1.0.0 en cada módulo, por MR como cualquier cambio.

  2. Fusionar ↗

    El Scrum Master aprueba y el MR entra a main.

  3. Verificar ↗

    El pipeline compila los siete proyectos en verde.

  4. Etiquetar ↗

    git tag -a v1.0.0 -m "Demo final" y git push origin v1.0.0.

  5. Publicar ↗

    Deploy → Releases → New release, con las notas del CHANGELOG.
